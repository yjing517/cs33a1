# BPE 训练优化复盘

## 1. 先跑通最直接的实现

我先建立 256 项单字节词表，加入特殊 token，然后在特殊 token 边界切分语料，分别预分词并转换成 UTF-8 字节序列。每轮统计相邻 pair、选择频次最高的一对，再从左到右应用合并。频次相同时选字典序最大的 pair。

这版通过了正确性测试，给后续优化留下了一个可以对照的基准。训练 500 项词表实测 13.98 秒。性能采样显示，最耗时的是应用合并和重新计数。每轮都访问了所有片段，相同片段也被反复处理。

## 2. 用 Counter 聚合重复片段

我把片段序列换成「字节片段 → 语料出现次数」的 Counter。片段内每出现一次相邻 pair，就将该片段的频次加到全局计数。每轮合并后，用累加汇总相同的新片段，保留语料中的出现次数。

这一步利用了一个性质：相同片段在同一轮会得到相同的合并结果。正确性和特殊 token 测试均通过，500 项词表训练降到 3.51 秒，约为初版的 3.98 倍速度。每轮仍要扫描全部不同片段，因此还有优化空间。

## 3. 用倒排索引缩小更新范围

我给每个聚合后的片段分配稳定 ID，并维护三份状态。

| 状态 | 含义 |
|---|---|
| word_list | 片段 ID 对应的当前字节序列和语料频次 |
| pair_counts | 每个 pair 在语料中的加权出现次数 |
| pair_to_words | 每个 pair 当前出现在哪些片段 ID 中 |

初始化时，片段内 pair 出现次数乘以片段语料频次，累加到全局计数。同一个 ID 在一个 pair 的索引集合中只出现一次。

每轮先按原来的规则选出最佳 pair，再取出其 ID 集合的快照。对这批片段分别统计合并前后的局部 pair 次数，用「新次数减旧次数，再乘片段频次」更新全局计数。局部次数从零变为正数时加入索引，从正数变为零时移除。全局计数归零时清理对应计数和索引项。稳定 ID 保留各自频次，即使两个 ID 后来对应相同的序列，它们的贡献仍会分别计入。

## 4. 用手算检查容易混淆的地方

假设片段 aaa 出现 2 次，ab 出现 4 次。相邻对 (a, a) 和 (a, b) 的加权频次都为 4，按字典序先合并 (a, b)。下一轮合并 (a, a) 时，aaa 变成两个 token：aa 和 a。原 pair 的全局贡献应扣 4，新 pair (aa, a) 应加 2。这个例子区分了相邻位置计数、非重叠合并和索引成员关系。

## 5. 验证与收获

增量版本的官方正确性、速度、特殊 token 测试全部通过。500 项词表训练低于 1.5 秒。3.95 秒是三项测试的总用时，单项训练的精确耗时未记录。速度已经达标，训练仍使用原有的最高频 pair 选择逻辑。

- 先验证输出再测速度。词表大小正确仍可能掩盖合并顺序错误，应该对照完整 merges。
- 优化可以分两步做。先减少相同片段的重复处理，再减少每轮触及的片段数。
- 加入倒排索引后，索引成员关系与加权次数要分别维护。调试时可用全量重算逐轮校验增量计数。
- 判断是否值得继续优化，依据测试门槛和实际耗时。
