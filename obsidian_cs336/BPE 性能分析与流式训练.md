# BPE 性能分析与流式训练

[[BPE 训练优化复盘]] 记录了从朴素 BPE 到倒排索引和增量计数的过程。本篇记录如何定位剩余瓶颈、验证优化，以及在 WSL 上完成完整 TinyStories 训练。

## 性能分析与实验设计

- **CPU、RAM、显存和 MiB。** CPU 执行预分词、统计和合并，RAM 存放语料、词频与索引，显存主要供 GPU 使用。这次 BPE 运行在 CPU 上。MiB 是容量单位，1 GiB = 1024 MiB，文件大小和内存占用都可以用它表示。
- **分开测速度和瓶颈。** 常规运行记录训练墙钟时间和峰值 RSS（进程峰值常驻内存），cProfile 用于定位函数的累计耗时。插桩会改变耗时，累计时间包含子调用。多进程场景还要明确统计的是单进程峰值还是整个进程树的内存。
- **先用小样本验证，再逐档放大。** 用同一输入和词表配置做前后对照。扩大样本时在完整文档边界截断，各次结果写入独立目录，设置超时和资源上限。
- **验证完整产物。** 重新加载 vocab 和 merges，核对连续 ID、256 个基础字节、唯一的特殊 token 和有序合并列表。对 10K 配置，达到目标词表时应有 10,000 − 256 − 1 = 9,743 次合并。最长 token 按字节长度统计，保留前导空格和所有并列项。

## 三项代码改动

| 改动 | 实现与验证重点 |
|---|---|
| 候选 pair 改用堆 | 增量更新后，把变动 pair 的当前计数压入堆。弹出时用全局计数判断快照是否有效，堆过大时重建。优先级保持频次降序，同频时选字节序最大的 pair。 |
| 先计频，再转字节 | 先累计预分词字符串的出现次数，每种字符串只转一次 UTF-8 字节元组，pair 统计继续使用原频次。 |
| 按完整文档流式读取 | 文本流增量解码 UTF-8，保留跨块识别特殊 token 所需的上下文，按完整段预分词。用小块测试跨块标记、连续标记、Unicode、换行和空输入，并与原切分逐项对照。 |

流式读取让语料缓冲主要受读取块和当前文档大小影响。词频表、倒排索引和堆仍驻留内存，总 RSS 还取决于不同片段和候选 pair 的数量。当前实现在没有特殊分隔符配置时沿用整段读取语义。

代码入口见 [bpe.py](../cs336_basics/bpe.py)，测量细节见 [流式实验报告](../outputs/bpe-experiments/streaming-report.md)。

## 对比分词器

在未参与对应样本训练的完整文档上，用两套 merges 对同一文本编码，以字节数除以 token 数。相同文本上，该值越高，token 越少。

| 样本分词器 | TinyStories 保留集（字节/token） | OpenWebText 保留集（字节/token） |
|---|---:|---:|
| TinyStories 200 MiB / 10K | 4.0743 | 3.1822 |
| OpenWebText 约 16 MiB / 32K | 3.9595 | 4.3066 |

两套分词器在各自的保留集上都用了更少的 token。训练规模、语料和词表大小同时变化，无法从这项对照分离单个变量的影响。

## 本次优化成果与实测指标

| 实验 | 训练耗时 | 峰值 RSS |
|---|---:|---:|
| TinyStories 5 MiB / 10K，最初基线 | 12.16 秒 | 202.45 MiB |
| TinyStories 5 MiB / 10K，堆与分段聚合 | 2.77 秒 | 37.36 MiB |
| TinyStories 5 MiB / 10K，再加入先计频后转字节 | 2.48 秒 | 34.9 MiB |
| TinyStories 200 MiB / 10K，先计频后转字节，整文件读取 | 27.58 秒 | 1,038.8 MiB |
| TinyStories 200 MiB / 10K，流式读取 | 23.12 秒 | 125.7 MiB |
| TinyStories 600 MiB / 10K，流式读取 | 65.89 秒 | 140.4 MiB |
| **完整 TinyStories / 10K，流式读取** | **250.95 秒** | **159.8 MiB** |
| OpenWebText 约 16 MiB / 32K，样本验证 | 22.20 秒 | 211.53 MiB |

- 5 MiB 从 12.16 秒降到 2.48 秒，约快 **4.9 倍**。原版 cProfile 中，查找最佳 pair 占 17.582 / 23.530 秒（74.7%）。堆和分段聚合优化后，字节转换占 3.230 / 6.055 秒（53.3%），据此再改为先计频。
- 同一份 200 MiB 样本改用流式读取后，峰值 RSS **下降 87.9%**，词表和有序 merges 逐项一致。流式版本从 200 MiB 扩展到全量，输入增至 **约 10.6 倍**，峰值 RSS 从 125.7 MiB 增到 159.8 MiB。
- 完整 TinyStories 共 **2,227,753,162 字节**，完成 **10,000 词表项和 9,743 次合并**，达到讲义的 30 分钟和 30 GB 上限内要求。三个最长 token 均为 15 字节，分别是含前导空格的 ` accomplishment`、` disappointment`、` responsibility`。
- 官方 BPE 测试 **3/3 通过**。OpenWebText 只有样本结果，得到 **32,000 词表项、31,743 次合并**，未开展全量训练。
